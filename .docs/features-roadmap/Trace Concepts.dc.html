◆ Trace, reimagined
From a diagram you look at → a tool you think with

Today the Trace only draws what feeds what — pretty lime connectors, no answers. But the authoring brief says the trace must let anyone answer two real questions: “what does this value drive?” and “why did this re-run?” — and the telestrator metaphor is about replay and annotation, not decoration. Three directions below, all over the same rate-limiter explorable, all reusing the reactive graph the runtime already records.

Trace today
Hover a value → lines appear from writer to readers. It confirms a link exists. You can’t click it, question it, replay it, or teach with it. Calm, but hollow.
What each option adds
1a explains a value (made-of · why · drives). 1b replays the propagation step by step. 1c lets an author narrate the flow as a saved walkthrough. Try each — they’re live.
1a
Explain this value — the Inspector
Explain-a-value · Impact preview

Click any $-value or output. A dockside inspector answers it in the value’s own voice: what it’s made of, why it last recomputed, and what it drives — the impact list is the “what will this affect” preview, always on. Serves author and reader identically.

1b
Replay the play — the Scrubber
Replay · Play-by-play

The telestrator’s core move. Change a value and the runtime doesn’t just settle — it replays the propagation one hop at a time: the changed input, the cell that re-runs, the value it writes, the view that repaints. Press play, or scrub any step. Readers see causality; authors demonstrate it.

1c
Guided trace — the Annotation
Guided walkthrough · Teaching

The telestrator literally: the author circles what matters, captions it, and sequences the marks into a numbered walkthrough saved with the doc. A reader steps Next / Prev; each step circles a value in gold and narrates it. This is trace as authored narration — the play drawn for someone else.
